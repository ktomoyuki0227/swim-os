## 1. 全体像：Stripe とは何か、なぜ使っているか

**Stripe** は、世界中で使われているオンライン決済サービスです。クレジットカードの処理・銀行への振込・自動引き落としなど、お金に関わる複雑な処理をすべて安全に代行してくれます。

swim.os では、以下の理由で Stripe を採用しています：

- カード番号などの機密情報を自社のサーバーに持たなくて済む（セキュリティが高い）
- コーチ（グループ管理者）への自動振込ができる
- サブスクリプション（月謝の自動引き落とし）に対応している

---

## 2. 3つの登場人物

Stripe の仕組みを理解するには、「3つの登場人物」を把握することが重要です。

```
【プラットフォーム】   ←→   【コーチ（グループ管理者）】   ←→   【スイマー（会員）】
  swim.os / Hidoll           各グループを管理する人             お金を払う側
  (Stripe アカウント)        (Connected Account)              (Customer)
```

| 登場人物 | Stripe での名称 | 役割 |
|---------|--------------|------|
| swim.os / Hidoll | Platform Account（プラットフォーム） | 全体を管理。手数料を受け取る |
| コーチ・グループ管理者 | Connected Account（接続アカウント） | 参加費・会費の入金先 |
| スイマー・会員 | Customer（カスタマー） | カードを登録してお金を払う |

---

## 3. 現在の動作モード

**現在はテストモードで動作しています。**

テストモードとは、実際のお金のやり取りは発生せず、模擬的な決済をシミュレーションできる開発用の環境です。テスト用のカード番号（`4242 4242 4242 4242` など）を使って動作確認ができます。

本番公開の前に、Stripe ダッシュボードで「本番モード（Live Mode）」に切り替える作業が必要です。

## 4. 各決済の流れ（種別ごと）

### 4.1 セッション参加費（都度払い）

スイマーがセッションに参加する際に発生する参加費です。

```
① スイマーが参加登録する
   ↓
② payment_status = "pending"（支払い待ち）として保存される
   ↓
③ 管理者が「開催確定」ボタンを押す
   ↓
④ Stripe で自動的に課金が実行される
   ↓
⑤ 課金成功 → payment_status = "paid" に更新
   課金失敗 → payment_status = "failed" に更新
```

**支払い方法の種類：**
- クレジットカード（Stripe 経由）
- 現金払い（管理者が「現金受取済み」を手動確認）
- 回数券（スタンプが自動的に1回分消費される）

**免除ルール（設定による）：**
- 管理者（admin）は無料
- 年会費・月謝会員は、グループの「免除設定」が ON の場合は無料

---

### 4.2 年会費（手動請求）

管理者が会員に対して年会費を請求するものです。

- 管理者が費用ページで「請求済み」に設定するか、Stripe でカード決済
- 支払いが完了したら管理者が「支払済」に変更する

---

### 4.3 月謝（サブスクリプション・自動引き落とし）

毎月決まった日に自動的にカードから引き落とされる月謝です。

```
① 管理者が「月謝 Subscription を開始」する
   ↓
② Stripe が毎月自動的に課金する
   ↓
③ 課金成功 → 支払い履歴に自動で追加される
   課金失敗 → 管理者・本人に通知が届く
```

**重要：** Subscription を開始するには、スイマーのカードが事前に登録されている必要があります。

---

### 4.4 回数券（ポイントカード）

まとめ買いして少しお得に使える仕組みです。

- 例：10回分を 9,000円（1回あたり 900円）で購入
- 購入時に Stripe でカード決済
- セッション参加のたびに残数が1つ減る
- 残数が3以下になると、管理者に警告バッジが表示される

---

## 5. プラットフォーム手数料（Hidoll / swim.os の収益）

スイマーがお金を払うたびに、設定した割合が自動的にプラットフォーム（swim.os 側）に入り、残りがコーチ（グループ管理者）の口座に振り込まれます。

**現在の設定：手数料率 10%**

```
例：スイマーが 2,000円 のセッション参加費を支払った場合

  スイマーが支払う金額    = 2,000円
  プラットフォーム手数料   = 200円（10%）
  コーチが受け取る金額    = 1,800円

  ※ この計算は自動で行われ、Stripe が振り分けてくれます
```

**手数料率の変更方法：**
データベース（DB）の `platform_settings` テーブルの `platform_fee_percent` の値を変更するだけです。コードの変更は不要です。

> 補足：「データベース」とは、システムの情報を保管している場所のことです。
> ちょうど Excel のような表があり、その中の数値を変えるだけです。

## 6. コーチ（グループ管理者）の口座登録（Stripe Connect）

グループを作成したコーチが入金を受け取るには、Stripe の口座登録（オンボーディング）を完了させる必要があります。

### 流れ

```
① グループ作成フロー（Step 6）で「口座情報を登録する」ボタンを押す
   ↓
② Stripe の専用ページに遷移する
   （メールアドレス入力 → 業種選択 → 銀行口座入力 → 本人確認）
   ↓
③ 登録が完了すると、グループの「口座設定完了」フラグが ON になる
   ↓
④ 以降、このグループの決済代金が自動で振り込まれるようになる
```

### 登録画面について（よくある疑問）

「グループ作成の途中でメールアドレスを入力する画面が出てきた」という経験をされたと思いますが、**これは正常な動作です。**

Stripe が独自に提供している口座登録フローで、アプリ側ではなく Stripe 社のサイトに遷移します。銀行口座や本人確認書類などの機密情報は、Stripe が直接収集・管理するため、swim.os のサーバーには一切届きません。これはセキュリティ上、非常に好ましい設計です。

テスト環境（現在の開発環境）では、登録内容はすべてダミーデータで OK です。

### 口座未登録の場合どうなるか

グループで口座が未登録の場合でも、スイマーへの課金自体は可能です。ただし、その売上は Stripe 上でプールされた状態になり、コーチへの自動振込は行われません。

## 7. スイマーのカード登録

スイマーが初回登録（オンボーディング）を完了する際、支払い方法（クレジットカード）を登録できます。

### 登録の流れ

```
① 新規登録のステップ7（お支払い）でカード情報を入力する
   ↓
② Stripe が安全にカード情報を確認・保存する
   （カード番号はアプリに届かず、Stripe が直接管理）
   ↓
③ Stripe から「カードID」が返ってくる
   ↓
④ そのIDをユーザーのアカウントと紐づけて保存する
   ↓
⑤ 以降、参加費・月謝などが自動で引き落とされるようになる
```

カード登録はスキップ可能です。後からプロフィールページの「お支払い」セクションでいつでも登録・変更できます。

### カードとアカウントの紐づけ方（技術的な説明）

ユーザーのアカウントには以下の2つの ID が保存されます：

| 保存場所 | 内容 |
|---------|------|
| `stripe_customer_id` | Stripe 上のユーザーID（Customer ID）|
| `stripe_payment_method_id` | 登録したカードのID |

Stripe 上では、この2つが紐づいており、自動課金時に正しいカードに請求されます。

## 8. Stripe ダッシュボードで確認・設定すべきこと

### 現在（開発中）に確認しておくこと

| 項目 | 場所 | 確認内容 |
|------|------|---------|
| Connect（接続） | ダッシュボード → Connect | 「有効化済み（Marketplace）」になっているか |
| Webhook（通知設定） | ダッシュボード → Webhooks | 7つのイベントが登録されているか（下記参照） |
| テストモード | 右上トグル | 「テストモード」になっているか |

### 登録済みの Webhook イベント一覧

Webhook とは、Stripe 側でイベントが起きたとき（例：決済成功）に、自動的にアプリ側に通知が届く仕組みです。

| イベント | 何が起きたとき |
|---------|-------------|
| `payment_intent.succeeded` | カード決済が成功したとき |
| `payment_intent.payment_failed` | カード決済が失敗したとき |
| `invoice.paid` | 月謝の請求書が支払われたとき |
| `invoice.payment_failed` | 月謝の引き落としが失敗したとき |
| `customer.subscription.updated` | 月謝の状態が変わったとき |
| `customer.subscription.deleted` | 月謝が解約されたとき |
| `account.updated` | コーチが口座登録を完了・変更したとき |

### 本番公開前に必要な作業

| 作業 | 内容 |
|------|------|
| ①本番モードへ切り替え | Stripe ダッシュボードの右上「テストモード」をOFF にする |
| ②本番用 API キーを取得 | ダッシュボード → 開発者 → API キー → 本番用の公開キー・秘密キーを取得 |
| ③環境変数を更新 | Vercel の環境変数（`STRIPE_SECRET_KEY` 等）をテスト用→本番用に差し替える |
| ④本番用 Webhook を設定 | ダッシュボード → Webhooks → 本番環境のURLでエンドポイントを追加する |
| ⑤本番用 Webhook シークレットを更新 | 新しいエンドポイントのシークレットキーを Vercel に設定する |

## 9. ローカル開発での既知の問題と対処法

### ① コールバック URL 問題（解決済み）

**問題：** ローカルで開発中にコーチの口座登録（Stripe Connect）を完了させると、ローカルのアプリではなく本番サイト（`swim-os-seven.vercel.app`）に遷移してしまい、登録完了が正しく記録されなかった。

**原因：** 環境設定ファイル（`.env.local`）に、ローカルのアドレスが指定されていなかったため、デフォルトで本番URLが使われていた。

**対処：** `.env.local` に `NEXT_PUBLIC_APP_URL=http://localhost:3000` を追加することで解決（2026-07-18 対応済み）。

---

### ② カードのデフォルト設定が更新されない問題（解決済み）

**問題：** オンボーディング（新規登録）でカードを登録しても、Stripe 側の「デフォルト支払い方法」が正しく設定されず、月謝の自動引き落としが失敗する可能性があった。

**原因：** カード登録後に Stripe の Customer の `invoice_settings.default_payment_method` を更新する処理が、オンボーディングフローに含まれていなかった。

**対処：** オンボーディング完了時に `updatePaymentMethod` を明示的に呼び出す処理を追加（2026-07-18 対応済み）。

## 11. 決済処理ロジックの場所と、設定を変えたいときの操作方法

### 11.1 決済の処理はどこに書かれているか

決済が実際に動く処理は、すべてコード（プログラム）の中に記述されています。
以下が主要な処理の場所です。

| 何が起きるか | コードの場所 | 備考 |
|---|---|---|
| セッション参加費の課金 | `actions/sessions.ts` → `confirmSession` 関数 | 管理者が「開催確定」を押したときに実行 |
| 月謝の Subscription 開始 | `actions/subscriptions.ts` → `startMonthlySubscription` 関数 | 管理者が月謝を開始したときに実行 |
| Stripe からの完了通知を受信 | `app/api/stripe/webhook/route.ts` | 決済成功・失敗をアプリに反映する |
| カード登録（新規登録時） | `app/(auth)/onboarding/page.tsx` | オンボーディング Step 7 |
| カード登録・変更（プロフィールから） | `app/(app)/payments/update-card-form.tsx` | お支払いページから操作 |
| コーチ口座登録（Connect） | `app/api/stripe/connect/onboarding/route.ts` | グループ作成フロー Step 6 |

これらはコードを直接編集する必要があるため、基本的には開発者が担当する部分です。

---

### 11.2 手数料率（何%か）の変更方法

手数料率だけは、**コードを変更せずに**データベース（DB）の管理画面から変更できます。

**変更手順：**

1. Supabase 管理画面（ブラウザ）にアクセス
2. 左メニューの「Table Editor」を開く
3. `platform_settings` テーブルを選択
4. `key = "platform_fee_percent"` の行の `value` 列を編集
5. 数値を変更して保存（例: `"10"` → `"8"` で 8% に変更）

**現在の設定値：**

| キー | 現在の値 | 意味 |
|------|---------|------|
| `platform_fee_percent` | `10` | スイマーの支払い金額から10%をプラットフォームが受け取る |

この変更はともくん自身が Supabase 管理画面から操作できます。Stripe の管理画面での操作は不要です。

---

### 11.3 Stripe の管理画面（ブラウザ）でしか設定できないもの

以下の項目は Stripe のブラウザ管理画面からのみ設定・確認できます。コードからは変更できません。

| 設定内容 | Stripe 管理画面のどこ | 変更タイミング |
|---|---|---|
| API キー（テスト↔本番の切り替え） | 開発者 → API キー | 本番公開時に1回 |
| Webhook エンドポイントの登録 | 開発者 → Webhook | 本番公開時に1回 |
| Connect（口座連携）機能の有効化 | Connect 設定 | 初回のみ（対応済み） |
| コーチへの振込スケジュール | Connected Account の設定 | 必要に応じて |
| 決済履歴・売上の確認 | ホーム → 支払い | 随時確認可能 |
| 返金処理 | 支払い → 該当の決済 → 返金 | 必要に応じて |

**注意：** 手数料率（`platform_fee_percent`）は Stripe 管理画面ではなく、Supabase の `platform_settings` テーブルで管理しています（上記 11.2 参照）。

---

### 11.4 まとめ：誰が何を操作できるか

| 操作内容 | 誰が操作するか | どこで操作するか |

## 12. 用語集

| 用語 | 意味 |
|------|------|
| Stripe | オンライン決済サービス。カード処理・自動振込・月額課金などを担当 |
| SetupIntent | カードを「登録するだけ」するための Stripe の仕組み。実際の課金はしない |
| PaymentIntent | 実際に「課金する」ための Stripe の仕組み |
| Subscription | 月謝のような「毎月自動で課金する」仕組み |
| Connected Account | Stripe Connect の「送金先口座」。コーチごとに1つ作成する |
| Customer | Stripe 上のスイマーのアカウント。カードを紐づけて管理する |
| Webhook | Stripe から「決済完了しました」などの通知をアプリに自動送信する仕組み |
| テストモード | 実際のお金は動かないデモ環境。開発・確認用 |
| 本番モード（Live Mode） | 実際のお金が動く環境 |
| application_fee_amount | PaymentIntent に設定するプラットフォーム手数料額（円単位） |
| transfer_data.destination | 送金先の Connected Account ID |
