 Rangers 決済(Stripe)機能 テスト・修正 総合報告
 作成日: 2026-08-22
================================================================================

本書は、決済(Stripe)関連で実施したレビュー・修正・テストの全体を
まとめたものです。時系列に沿って、(1)事前レビューで見つかった修正、
(2)テスト手順書の整備、(3)年会費の自動課金対応、(4)テストで新たに
発見した不具合の修正、(5)自動テストによる検証結果、(6)今後の対応予定、
の順に記載しています。


================================================================================
 1. 決済基盤のセキュリティ・信頼性レビューと修正
================================================================================
年会費対応に着手する前段として、決済に関わる既存コード全体をレビューし、
以下の問題を修正済みです。

--------------------------------------------------------------------------------
【顧客の決済情報が不正に書き換えられないようにする保護を追加】
--------------------------------------------------------------------------------
会員のStripe顧客ID・支払い方法ID・チームの受け取り口座IDについて、管理者権限を
持たない操作から書き換えができないようデータベース側で保護する仕組みを追加。

--------------------------------------------------------------------------------
【会費・決済履歴が誤って消えないようにする保護を追加】
--------------------------------------------------------------------------------
セッション(練習会・大会等)や参加申込、参加申請のレコードを削除した際、
連動して会費・決済の履歴データまで自動的に削除されてしまう設定になっていたため、
履歴が残るように変更。

--------------------------------------------------------------------------------
【現金払いの会費処理で二重更新が起きないよう修正】
--------------------------------------------------------------------------------
管理者が現金払いの会費を「支払い済み」にする操作について、複数人が同時に
操作した場合に二重処理が起こる可能性があったため、原子的な更新処理に修正。

--------------------------------------------------------------------------------
【Stripeからの決済通知(Webhook)処理でエラーが握りつぶされる問題を修正】
--------------------------------------------------------------------------------
Stripeからの決済完了通知を受信した際、内部処理でエラーが発生しても正常応答を
返してしまい、実際には課金されているのに記録が残らない状況になり得る実装
だったため、エラー発生時は正しく再送を促すよう修正。

--------------------------------------------------------------------------------
【Stripe連携コードがブラウザ側に混入しないよう修正】
--------------------------------------------------------------------------------
Stripeの秘密鍵を扱うコードが、意図せずブラウザ向けのコードに含まれてしまう
可能性があったため、サーバー専用であることを明示する設定を追加。

--------------------------------------------------------------------------------
【使われていない旧機能の削除】
--------------------------------------------------------------------------------
サービス開始初期に構想されていた個人レッスン予約・決済のための旧テーブル群
(現在は完全に未使用)を、依存関係の再調査を行った上で削除。

 2. 決済テスト手順書の整備
================================================================================
決済関連の動作確認を毎回もれなく・安全に行えるよう、手順書
「PAYMENT_TESTING_GUIDE.md」を作成しました。

主な内容:
  ・テストモードでは実際のお金は一切動かないことの説明
    (本物のカード・銀行口座情報を入力する必要はない旨)
  ・現在テストモードで動作しているかどうかの確認方法
  ・Stripe公式のテスト用カード番号・銀行口座情報の一覧
  ・チームの受け取り口座設定、会員のカード登録、月謝・年会費の課金、
    セッション参加費の課金、現金払い、キャンセル時の返金、手数料計算など、
    決済に関わる全シナリオの確認手順とチェックリスト


================================================================================
 3. 年会費のStripe自動課金対応
================================================================================
これまで年会費は現金払いのみの運用でしたが、月謝と同様にクレジットカードに
よる自動課金に対応しました。

  ・会員がカード登録済みの状態でチームに参加すると、年会費が自動でカード
    課金される(月謝と同じ仕組み・年1回のサブスクリプション)
  ・カード未登録の場合は、従来通り現金払いとして扱われる(後方互換あり)
  ・決済手順書についても、年会費の課金テストシナリオを追加する形で更新


================================================================================
 4. テストで発見した重大な不具合とその修正
================================================================================
年会費の自動課金機能をテストする過程で、月謝についても同様の重大な不具合が
あることを発見しました。

【不具合の内容】
Stripeの仕様上、サブスクリプション作成直後の初回請求は「明示的に確定処理を
呼び出さない限り自動では課金されない」仕様でした。この確定処理が実装から
漏れていたため、月謝会員のサブスクリプションは作成されるだけで、実際には
カードへ一度も課金されていなかったことが判明しました。

【対応】
確定処理を追加し、月謝・年会費どちらも正しく自動課金されるよう修正済みです。

 5. 自動テストによる検証結果
================================================================================
Stripeのテスト環境(実際の資金移動は発生しない検証用モード)上で、
ヘッドレスブラウザによる自動操作テストを実施。実際のログイン → 招待コードでの
年会費会員参加 → カード課金 → 決済結果の反映まで、一連の流れを人手を介さず
自動で検証しました。

[年会費の自動課金]                                              確認結果
  ・サブスクリプションの作成(年次課金)                          OK
  ・登録済みカードへの自動課金                                    OK
  ・決済完了後のWebhook通知の受信                                 OK
  ・会費記録への正しい反映(種別・期間・金額・支払方法・状態)      OK
  ・会員ステータスの同期                                          OK
  ・決済履歴(通帳)画面への表示                                  OK

[月謝の自動課金(回帰確認)]
  ・上記修正により、月謝についても同様に全項目                    OK

--------------------------------------------------------------------------------
今回のテスト範囲に含まれなかった項目
--------------------------------------------------------------------------------
・年会費の「翌年以降」の自動更新課金
    → Stripe管理画面上の時間シミュレーション機能が必要なため、自動テスト
      環境では検証未実施。1回目の課金処理自体は修正済みのため、Stripeの
      標準的な請求サイクルに則り正常に動作する見込み。
・年会費の課金失敗時(カード拒否等)の挙動
    → テスト用の疑似カードの制約により、実環境での再現が困難だった。
      コード上は成功時と同一の分岐処理を使用しているため動作する可能性は
      高いが、実機確認は未実施。
・その他の決済関連機能(Stripe口座連携設定、セッション参加費決済、
  現金払い記録、キャンセル時の返金、手数料計算)
    → 今回は年会費対応を優先したため未着手。

 6. 今後の対応予定
================================================================================
■ 優先度: 高
--------------------------------------------------------------------------------
1. 年会費の翌年自動更新課金の実機確認
     Stripeダッシュボード上の時間シミュレーション機能を使い、1年後の
     自動課金が正しく行われることを手動で一度確認する。

2. 年会費・月謝の課金失敗時の挙動の実機確認
     カードが途中で使えなくなった場合に、正しく失敗通知・状態遷移
     (未払い状態への変更)が行われることを確認する。

■ 優先度: 中(未着手の決済関連シナリオ)
--------------------------------------------------------------------------------
3. Stripe Connect(チームの受け取り口座設定)のテスト
4. セッション参加費決済(申込〜開催確定時の課金、失敗時の再試行)のテスト
5. 現金払いの記録・取り消しのテスト
6. セッション中止時の返金処理のテスト
7. プラットフォーム手数料・チームへの送金額のテスト

■ 補足
--------------------------------------------------------------------------------
・今回作成した自動テストスクリプト(scripts/test-*.mjs)はプロジェクトに残して
  あるため、3〜7についても同様の手法で自動テストを拡張していく想定。
・本番(実際に課金が発生するモード)への切り替えは、上記すべての検証が
  完了してから別途判断する。
